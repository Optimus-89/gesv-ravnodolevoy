# PRD: Веб-калькулятор ГЭСВ для равнодолевого графика платежей

**Версия документа:** 1.0
**Тип продукта:** веб-приложение (одностраничное, клиентское, без сервера)
**Статус:** описывает уже реализованный функционал (v1) для формализации требований

---

## 1. Назначение и контекст

Инструмент предназначен для расчёта **ГЭСВ (годовой эффективной ставки вознаграждения)** по кредитам с **равнодолевым графиком погашения основного долга**, с поддержкой:

- раздельных льготных периодов по основному долгу (ОД) и по вознаграждению (%);
- гибкой периодичности погашения ОД и % (не обязательно ежемесячно);
- трёх способов распределения процентов, накопленных за льготный период;
- единовременной и периодической комиссий;
- корректировки дат платежей с учётом выходных и праздничных дней Республики Казахстан.

Целевой пользователь — сотрудник финансовой организации (кредитный/риск-аналитик, методолог), которому нужно быстро промоделировать график и получить ГЭСВ для проверки условий кредита или сравнения сценариев, без обращения к Excel.

---

## 2. Цели и не-цели

**Цели:**
- Дать точный, воспроизводимый расчёт ГЭСВ методом XIRR по фактическому денежному потоку.
- Поддержать все комбинации входных параметров без падения расчёта (защититься от деления на 0, незакрытых остатков и т.д.).
- Дать пользователю возможность управлять параметрами по каждому месяцу отдельно (льготы, вес распределения).
- Работать полностью локально в браузере — без сервера, без передачи данных куда-либо.

**Не-цели (вне рамок v1):**
- Не реализуется аннуитетный (равноплатежный) график — только равнодолевой (equal principal).
- Не поддерживается сохранение/загрузка сценариев между сессиями (нет базы данных, нет localStorage — см. раздел 8).
- Не ведётся многопользовательский/серверный режим, авторизация, история расчётов.
- Не учитываются региональные праздники за пределами общереспубликанского календаря РК.
- Не гарантируется юридическая точность календаря праздников на годы, где даты ещё официально не утверждены (см. 6.3).

## 3. Пользовательские сценарии (User Stories)

1. Как кредитный аналитик, я хочу задать сумму, ставку, срок и дату выдачи, чтобы увидеть график платежей и итоговую ГЭСВ.
2. Как аналитик, я хочу отметить конкретные месяцы как льготные по ОД и/или по %, чтобы смоделировать реструктуризацию/отсрочку.
3. Как аналитик, я хочу выбрать, как накопленные за льготу проценты будут распределены (на ближайший платёж / на все платежи / вручную), чтобы сравнить влияние на ГЭСВ.
4. Как аналитик, я хочу задать периодичность погашения ОД и % отдельно (месяц/квартал/полугодие/год/в конце срока), чтобы смоделировать неаннуитетные продукты (например, бридж-кредиты с погашением в конце срока).
5. Как аналитик, я хочу учитывать комиссию за выдачу и ежемесячную комиссию за обслуживание, чтобы ГЭСВ отражала полную стоимость кредита.
6. Как аналитик, я хочу, чтобы даты платежей не выпадали на выходные и праздники РК, а автоматически переносились на ближайший рабочий день, как это происходит в реальном обслуживании кредита.
7. Как аналитик, я хочу выгрузить итоговый график в CSV для дальнейшей работы в Excel.

## 4. Входные параметры

### 4.1 Параметры кредита

| Поле | Тип | По умолчанию | Ограничения |
|---|---|---|---|
| Сумма кредита | число | 1 000 000 | > 0 |
| Ставка, % годовых | число | 20 | ≥ 0 |
| Дата выдачи | дата | текущая дата | обязательна |
| Срок, мес. | целое | 12 | 1–60 |
| База расчёта дней в году | число | 365 | обычно 365 или 366 |
| Периодичность погашения ОД | список | «Ежемесячно» | см. 4.2 |
| Периодичность погашения % | список | «Ежемесячно» | см. 4.2 |
| Способ распределения пула % | список | «Ближайший платеж» | см. 4.3 |
| Комиссия за выдачу, % от суммы | число | 0 | ≥ 0 |
| Комиссия за выдачу, фикс. сумма | число | 0 | ≥ 0 |
| Ежемесячная комиссия, % от остатка | число | 0 | ≥ 0 |
| Ежемесячная комиссия, фикс. сумма | число | 0 | ≥ 0 |

### 4.2 Периодичность погашения (независимо для ОД и для %)

Варианты: **Ежемесячно / Ежеквартально / Раз в полгода / Раз в год / В конце срока**.

Определяет интервал в месяцах между датами фактического платежа: 1 / 3 / 6 / 12 / срок кредита соответственно. Последний месяц срока **всегда** является датой платежа независимо от интервала (форсированное закрытие обязательства).

### 4.3 Способ распределения пула процентов, накопленных за льготу по %

- **«Ближайший платеж»** — весь накопленный пул списывается целиком на первую же последующую нельготную дату уплаты %.
- **«Все платежи»** — пул равномерно распределяется на все оставшиеся (нельготные) даты уплаты % до конца срока; при появлении нового пополнения пула распределение на оставшиеся даты пересчитывается.
- **«Вручную»** — для каждого месяца задаётся вес 0–1 (доля **текущего остатка пула**, списываемая в этот месяц). На последней оставшейся дате уплаты % остаток пула списывается полностью автоматически, независимо от заданного веса (гарантия закрытия к концу срока).

### 4.4 Таблица по месяцам (1..Срок)

Для каждого месяца i задаются:

| Поле | Тип | По умолчанию |
|---|---|---|
| Льгота по ОД | 0/1 (флаг) | 0 |
| Льгота по % | 0/1 (флаг) | 0 |
| Вес ручного распределения | число 0–1 | 0 |

Таблица должна перестраиваться при изменении срока (число строк = срок).

## 5. Логика расчёта (расчётное ядро)

### 5.1 Общие обозначения (для месяца i = 1..Срок)

- `balance` — остаток ОД на начало месяца.
- `dueOD(i)`, `duePct(i)` — флаги «в этом месяце физически происходит платёж по ОД / по %» (см. 5.2).
- `graceOD(i)`, `gracePct(i)` — флаги льготы, заданные пользователем.
- `bucket` — сумма %, начисленных с момента последней фактической выплаты % (накопитель между датами платежа при периодичности реже месяца).
- `pool` — сумма %, отложенных льготой по % и ожидающих распределения.

### 5.2 Определение дат платежа (due-даты)

```
interval = { Ежемесячно:1, Ежеквартально:3, Раз в полгода:6, Раз в год:12, В конце срока:Срок }[периодичность]
due(i) = 1, если (i mod interval == 0) ИЛИ (i == Срок), иначе 0
```
Применяется отдельно для ОД (`intervalOD`) и для % (`intervalPct`).

### 5.3 Погашение основного долга

```
remainingOD(i) = количество j из [i..Срок], где dueOD(j)=1 И graceOD(j)=0
principal(i) = balance / remainingOD(i),  если dueOD(i)=1 И graceOD(i)=0 И remainingOD(i)>0
             = 0,  иначе
balance_end(i) = balance(i) - principal(i)
```

Льгота по ОД в месяце i просто исключает i из знаменателя — остаток равномерно перераспределяется по оставшимся неотложенным датам. Специальной логики распределения (как для %) для ОД не требуется.

### 5.4 Начисление и уплата процентов

```
interestAccrued(i) = balance(i) * ставка / база_дней * дней_в_периоде(i)
amountReady(i) = bucket_start(i) + interestAccrued(i)

remainingPct(i) = количество j из [i..Срок], где duePct(j)=1 И gracePct(j)=0
poolStart(i) = pool на начало месяца i

если duePct(i)=1 И gracePct(i)=0:
    interestPaid(i) = amountReady(i)
    poolAdd(i) = 0
иначе:
    interestPaid(i) = 0
    poolAdd(i) = amountReady(i), если gracePct(i)=1, иначе 0

bucket_end(i) = 0, если (duePct(i)=1 ИЛИ gracePct(i)=1), иначе amountReady(i)
```

### 5.5 Распределение пула (доплата из пула)

Применяется, только если `duePct(i)=1 И gracePct(i)=0`:

```
Ближайший платеж:  distribution(i) = poolStart(i)
Все платежи:        distribution(i) = poolStart(i) / remainingPct(i)   (0, если remainingPct(i)=0)
Вручную:             distribution(i) = poolStart(i),                    если remainingPct(i)=1 (последняя дата — форс. списание)
                     distribution(i) = poolStart(i) * вес(i),           иначе
```
Во всех остальных случаях `distribution(i) = 0`.

```
pool_end(i) = poolStart(i) + poolAdd(i) - distribution(i)
```

### 5.6 Комиссии

```
Комиссия за выдачу (единоразово, t=0) = Сумма*feePct + feeFix
Комиссия за период (i=1..Срок) = svcFix + svcPct * balance(i)
```

### 5.7 Итоговый платёж и денежный поток

```
totalInterest(i) = interestPaid(i) + distribution(i)
totalPayment(i)  = principal(i) + totalInterest(i) + комиссия_за_период(i)

Денежный поток для ГЭСВ:
  t=0:      -(Сумма - Комиссия_за_выдачу)
  t=1..N:   totalPayment(i), на фактическую (скорректированную, см. раздел 6) дату платежа
```

### 5.8 Расчёт ГЭСВ

ГЭСВ = **XIRR** денежного потока по фактическим датам:

```
XNPV(rate) = Σ CF_i / (1+rate)^((date_i - date_0)/365)
ГЭСВ = rate, при котором XNPV(rate) = 0
```

Метод решения: бисекция на интервале rate ∈ (-0.999999, до 10, с адаптивным расширением верхней границы), точность 1e-9, до 300 итераций. Реализация не должна зависеть от внешних библиотек.

### 5.9 Контрольные (проверочные) показатели

После расчёта графика обязательны проверки, отображаемые пользователю:

| Проверка | Ожидаемое значение |
|---|---|
| Сумма всех `principal(i)` | = Сумма кредита |
| `pool_end` на последней дате уплаты % | 0 |
| `bucket_end` на последней дате уплаты % | 0 |
| `balance_end` на последнем месяце срока | 0 |

Отклонение по модулю > 0.5 (в валюте кредита) считается ошибкой расчёта и должно визуально подсвечиваться (см. 7.3).

## 6. Календарь: перенос дат платежей (РК)

### 6.1 Требование

Дата, рассчитанная по графику (`issueDate + i месяцев`), не должна выпадать на выходной или праздничный день РК. Если выпадает — дата **переносится вперёд** на ближайший фактический рабочий день (следующая доступная рабочая дата, following business day convention). Скорректированная дата используется во всех дальнейших расчётах (число дней в периоде, денежный поток для XIRR) — то есть период между двумя платежами считается между их фактическими (скорректированными) датами.

### 6.2 Состав нерабочих дней

- Суббота, воскресенье.
- Государственные и национальные праздники РК (фиксированные ежегодные даты):
  - 1–2 января — Новый год
  - 8 марта — Международный женский день
  - 21–23 марта — Наурыз мейрамы
  - 1 мая — День единства народа Казахстана
  - 7 мая — День защитника Отечества
  - 9 мая — День Победы
  - 6 июля — День Столицы
  - 25 октября — День Республики
  - 16 декабря — День Независимости
  - 15 марта — День Конституции РК (действует с 2027 года; в переходном 2026 году праздник не отмечается ни 30 августа, ни 15 марта — согласно закону о переносе даты, вступившему в силу 01.07.2026)
- Дни без механизма переноса (являются нерабочими всегда, но сами не создают дополнительный перенесённый выходной):
  - 7 января — православное Рождество
  - Первый день Курбан-айта (дата плавающая, см. 6.3)

### 6.3 Курбан-айт (плавающая дата)

Дата определяется лунным календарём и официально объявляется Духовным управлением мусульман Казахстана незадолго до праздника. В продукте:

- Для 2025 и 2026 годов используются подтверждённые официальные даты (6 июня 2025; 27 мая 2026).
- Для всех остальных лет дата **аппроксимируется** (сдвиг ~11 дней назад в год от ближайшего известного года) и помечается в интерфейсе как ориентировочная.
- Требование к продукту: список известных дат должен быть легко обновляемым (константа в коде), чтобы дату можно было уточнить, когда она будет официально объявлена.

### 6.4 Механизм переноса выходного дня (перенос для фиксированных праздников)

Если фиксированный праздник (из списка 6.2, кроме Рождества и Курбан-айта) выпадает на субботу или воскресенье, следующий за ним свободный рабочий день также становится нерабочим (компенсирующий перенос). Алгоритм должен обрабатывать цепочки (например, Наурыз 21–23 марта, если 21 и 22 числа — выходные, создаёт два последовательных переноса).

Правило проверено и должно воспроизводить официально известные переносы 2026 года:
- 8 марта (вс) → выходной 9 марта
- 9 мая (сб) → выходной 11 мая
- 21 марта (сб) → выходной 24 марта; 22 марта (вс) → выходной 25 марта
- 25 октября (вс) → выходной 26 октября

### 6.5 Отображение

Платежи, дата которых была перенесена, должны быть визуально помечены в таблице графика (например, значком с всплывающей подсказкой «дата перенесена с выходного/праздничного дня»).

Дата выдачи кредита пользователем **не переносится автоматически** — предполагается, что она выбрана осознанно (банк не выдаёт кредиты в нерабочие дни), перенос применяется только к расчётным датам платежей.

## 7. Требования к интерфейсу

### 7.1 Общая структура

Двухколоночная раскладка (адаптивная, в одну колонку на экранах уже 980px):

- **Левая колонка:** параметры кредита + таблица льгот по месяцам (прокручиваемая, перестраивается по сроку) + кнопки «Рассчитать» и «Экспорт CSV».
- **Правая колонка:** крупный индикатор ГЭСВ, блок проверочных показателей, полная таблица графика платежей.

### 7.2 Индикатор ГЭСВ

- ГЭСВ отображается в процентах **с округлением до сотых** (2 знака после запятой), например `27.33%`.
- Расчёт выполняется мгновенно по нажатию «Рассчитать», без перезагрузки страницы.

### 7.3 Проверочные показатели

Четыре плитки: «Погашено ОД», «Остаток пула», «Остаток бакета», «Остаток долга». Значения, которые должны быть равны нулю (кроме «Погашено ОД»), подсвечиваются зелёным при |значение| < 0.5 и красным — в противном случае.

### 7.4 Таблица графика

Колонки: № платежа, Дата (с пометкой переноса), Due ОД, Due %, Льгота ОД, Льгота %, Остаток на начало, Погашение ОД, % к уплате (итого), Комиссия, Итоговый платёж, Остаток на конец. Строки с активной льготой (ОД или %) визуально выделяются (например, светлым фоном).

### 7.5 Обработка ошибок ввода

- Некорректные или отсутствующие значения (например, срок вне диапазона 1–60, сумма ≤ 0) должны блокировать расчёт и выводить понятное сообщение об ошибке в отдельном блоке, без падения интерфейса.
- Сообщение об ошибке должно быть сформулировано по-человечески («Срок должен быть от 1 до 60 месяцев»), не как текст исключения.

### 7.6 Экспорт

Кнопка «Экспорт CSV» выгружает полный график (включая служебные колонки: начислено %, добавка в пул, доплата из пула, пул на конец, бакет на конец) в файл `gesv_grafik.csv` с разделителем `;` и BOM для корректного открытия в Excel с кириллицей.

## 8. Нефункциональные требования

- **Технологии:** чистый HTML/CSS/JavaScript, без сборки, без обязательных внешних зависимостей во время выполнения (кроме шрифтов через Google Fonts — деградация допустима при отсутствии интернета). Никаких серверных вызовов.
- **Хранение данных:** запрещено использовать localStorage/sessionStorage (ограничение окружения предпросмотра); все данные держатся в памяти на время сессии.
- **Производительность:** расчёт графика на 60 месяцев с полной таблицей льгот должен выполняться мгновенно (без заметной задержки, < 100 мс).
- **Точность расчёта:** ГЭСВ должна совпадать (до 6–8 значащих цифр) с эталонной реализацией на Python и с формулой Excel `XIRR()` при одинаковых входных данных — используется как критерий регрессионного тестирования.
- **Локализация:** интерфейс и форматирование чисел — русский язык, разделитель разрядов — пробел/точка по правилам `ru-RU`.
- **Доступность:** видимый фокус на полях ввода, читаемый контраст текста, работоспособность при отключённой анимации (анимации в продукте отсутствуют).
- **Адаптивность:** корректное отображение на экранах шириной от ~360px (мобильные) до широких десктопных мониторов.

## 9. Критерии приёмки (Acceptance Criteria)

1. При параметрах по умолчанию (без льгот, ежемесячно, без комиссий, ставка 20%, сумма 1 000 000, срок 12 мес.) расчёт даёт ГЭСВ, все проверочные показатели — «зелёные» (в пределах допуска).
2. Если хотя бы один месяц отмечен как «Льгота по ОД», сумма всех платежей по ОД за весь срок по-прежнему равна сумме кредита.
3. Если хотя бы один месяц отмечен как «Льгота по %», при любом из трёх способов распределения остаток пула на конец срока равен 0.
4. При периодичности ОД/% реже «Ежемесячно» платежи по соответствующей статье возникают только в даты, кратные выбранному интервалу, и обязательно в последнем месяце срока.
5. Изменение суммы комиссии за выдачу и/или ежемесячной комиссии видимо влияет на итоговую ГЭСВ (увеличивает её при увеличении комиссий).
6. Ни одна расчётная дата платежа в таблице графика не приходится на субботу, воскресенье или праздник РК из списка 6.2–6.3; при совпадении с выходным/праздником дата в таблице соответствует ближайшему рабочему дню и помечена как перенесённая.
7. Приложение не завершается с ошибкой ни при одной допустимой комбинации входных параметров (включая экстремальные: срок=1, срок=60, все месяцы льготные, ставка=0, комиссии=0).
8. Экспортированный CSV открывается в Excel без потери кириллицы и с корректным разделением по столбцам.

## 10. Известные ограничения и риски

- Даты Курбан-айта для лет, официально ещё не объявленных ДУМК, — расчётные, не гарантированно точные; список известных дат требует периодического обновления в коде.
- Модель не учитывает возможные точечные постановления Правительства РК о переносе рабочих дней сверх стандартного механизма закона «О праздниках» (случаются эпизодически для формирования длинных выходных).
- Ручной способ распределения пула («Вручную») определяет вес как долю от **текущего**, а не от исходного остатка пула — это должно быть явно объяснено пользователю в интерфейсе (см. 7 — уже реализовано как заметка в панели).
- Однопользовательский локальный расчёт — нет сохранения сценариев между сессиями; при обновлении страницы все введённые данные сбрасываются к значениям по умолчанию.
